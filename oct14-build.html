For whoever builds this site next

How to rebuild the site

Two pages are generated. Getting the order wrong loses a nav link silently.

The order:

portfolio/build.py → keying/build.py → nav/build_nav.py → both verify.py → dev/audit_site.py

Why the order matters

build.py emits the nav block its template last carried. build_nav.py is the only thing that reads the nav map. Run a build after the nav builder and the page silently drops any nav item added since — no error, no failing check, and the page looks perfect.

That happened on Oct 14: portfolio.html was rebuilt after the nav builder ran and dropped the link to the Oct 15 agenda. One line.

The shipped HTML is not the source

portfolio.html and keying.html are generated. Editing them in the site repo works until the next build, which reverts everything. On Oct 14 a session fixed the shipped HTML without the generators, and the next run of either builder would have put both pages back to the Oct 6 estimates.

If you change what those two pages say, change it in portfolio/data.py or keying/data.py and rebuild. now.html, index.html and strategy.html are not generated and are edited directly.

verify.py defaults to the wrong file

Both verifiers default to the stale copy sitting next to them rather than the live page. Run them that way and they report a clean pass while the real page is broken — this reported “251 checks, 0 FAILURES” on Oct 14 while the live page had 54 errors. Always pass the site path explicitly.

Then run the audit

dev/audit_site.py checks the things a diff cannot: that every internal link resolves, that nothing is unreachable, that no countdown points at a past date, that no page asserts a figure known to be wrong, that no page describes a past event as upcoming, and that both generated pages match their builders exactly.

It was written after a pass that verified its own edits carefully and still shipped a meeting agenda nothing linked to. Checking what you changed cannot find what is missing.
